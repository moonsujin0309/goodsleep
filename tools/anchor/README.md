# 목소리 앵커

`voice.wav` 가 **앱 전체 나레이션의 목소리를 정한다.** 함부로 바꾸지 말 것 —
이 파일을 바꾸면 788개 토막을 전부 다시 뽑아야 하고, 목소리가 통째로 달라진다.

## 왜 필요한가 (2026-08-26)

그전까지는 `tts_voxcpm.DESIGN` 의 **말로 된 묘사**로 목소리를 만들었다.
그런데 조각마다 `model.generate()` 를 새로 부르고, 그때마다 묘사에서 목소리를
새로 뽑는다. **시드를 42로 고정해도 막히지 않는다.**

실측(racing 한 세션, 음량·속도를 맞춘 뒤 MFCC 거리. 호흡을 0으로 둠):

| 층 | 앵커 전 | 앵커 후 |
|---|---|---|
| 정착 | 67.4 | 20.6 |
| 이완 | 61.4 | 22.4 |
| 심상 | 41.3 | 27.9 |
| 소실 | 35.9 | 17.6 |

사용자가 "이상하다"고 짚은 정착·이완이 정확히 가장 먼 둘이었다.
**음량이나 속도로는 못 맞추는 차이다** — 둘 다 맞춰 놓고도 남았다.

덤으로 생성이 안정됐다. 5조각 전부 한 덩어리로 나왔고(전엔 심상 2·소실 4로 쪼개졌다),
속도 보정이 2개에서 0개로 줄었다. 앵커가 목소리뿐 아니라 발화 리듬까지 잡아 준다.

## 앵커가 말 속도도 정한다 (2026-08-26)

목소리만이 아니다. **앵커를 늘려 두면 모델이 그만큼 느리게 말한다.**
실측: 앵커를 1.25배로 늘리니 결과가 **1.27배** 느려졌다. 거의 그대로 따라간다.

그래서 `SLOW`(굽기 직전 시간축 늘리기)를 **껐다**. 늘리기에는 1.45배라는 천장이
있지만(그 위는 자음이 뭉개진다) 앵커를 통한 감속은 **가공이 아니라 생성**이라
음질 손해도 천장도 없다. **더 느리게 하려면 `SLOW` 가 아니라 이 파일을 늘린다.**

다만 앵커를 많이 늘릴수록 앵커 자체에 가공 흔적이 남고, 조각 사이 음색이
조금씩 벌어진다 (1.25배에서 거리 14~21, 1.43배에서 16~39). 1.43배까지는 확인했다.

## 지금 파일

`racing/breath/b1` 의 네 번째 토막에서 떴다. 사용자가 여러 판을 듣고 고른 목소리다.
거기에 **1.43배 감속**을 걸어 둔 상태다.

```
대사   내쉬는 숨이 길어지면 몸은 안전하다고 판단합니다.
길이   4.50초 (원본 3.16초 × 1.43) · 48kHz
결과   0.139 초/글자
```

`tts_voxcpm.ANCHOR_TEXT` 가 이 대사와 **정확히** 같아야 한다. 다르면 모델이
엉뚱한 발음을 이어 붙인다.

## 다시 만들 때

굽는 단계에서 걸린 것들을 되돌려 **모델이 실제로 뱉었던 파형**에 가깝게 만든다.

1. 쓸 토막의 mp3 를 고른다 (발화 3초 안팎, 침묵 적고, 문장 하나가 온전한 것)
2. `SLOW` 가 켜져 있었다면 `atempo` 로 되돌린다 (지금은 1.0 이라 할 게 없다)
3. 그 조각에 걸렸던 `음량 N배`(생성 로그에 찍힌다) 로 나눈다
4. 앞뒤 침묵을 잘라낸다
5. **원하는 말 속도만큼 늘린다** (지금 1.43배). 이게 결과 속도를 정한다
6. `voice.wav` 로 저장하고 `ANCHOR_TEXT` 를 그 토막 대사로 맞춘다
7. **전량 재생성**한다 (`--force`)

속도만 바꾸고 싶으면 1~4를 건너뛰고 지금 `voice.wav` 에 `atempo` 를 한 번 더
거는 것이 아니라, **원본에서 다시 만든다** — 늘린 것을 또 늘리면 흔적이 쌓인다.
원본은 `racing/breath/b1-3.mp3` 에서 위 절차로 언제든 다시 뜰 수 있다.

앵커가 없으면 `tts_voxcpm.speak()` 가 예전처럼 `DESIGN` 묘사로 돌아간다.
파일을 지우면 그 순간부터 목소리가 조각마다 흔들린다는 뜻이다.
